# 粮食采样机器人项目完整运行流程说明

## 一、当前结论

项目从“开机启动 → UI 创建任务 → 导航 → 下管/拧管 → 抽粮/分仓 → 返回”的软件链路已经基本形成。

底层 ROS 服务、PCA9685、X2P 升降电机和遥控底盘链路已具备运行条件，但当前代码还不能直接称为“完整实机全流程”，主要有以下四个问题：

1. UI 创建流程控制器后，没有启用真实机构，默认会走模拟等待。
2. 当前启动服务没有启动导航程序，必须使用假到达命令或另外启动导航节点。
3. 风机 CH7 仍是占位通道，正式抽粮步骤不会真正启动风机。
4. 深度计算按“一次动作 = 1 米”，但每次 X2P 实际只运动 20 cm，需要确认机械结构或修改代码。

## 六、完整任务状态机

主要文件：

```text
src/grain_sampling_workflow/state_machine.py
src/grain_sampling_workflow/orchestrator.py
src/grain_sampling_workflow/ros_bridge.py
```

完整流程：

| 阶段 | 执行效果 |
|---|---|
| 1. INIT | UI 显示已就绪，等待点击 |
| 2. RECORD_START | 读取 `/Odometry`，记录机器人出发坐标 |
| 3. NAVIGATE_TO_POINT | 向 `/move_base_simple/goal` 发布采样点 |
| 4. ARRIVED_PROMPT | 到达后提示连接管道、风机等 |
| 5. PRESS_AND_SUCTION | 夹持 → X2P 下压 20 cm → 松开 → X2P 上升 20 cm → 再夹持 → 启动风机 |
| 6. ADD_PIPE_PROMPT | 深度不够时提示人工加管 |
| 7. REPEAT_UNTIL_DEPTH | 拧紧 → 松开 → 夹紧，然后再次执行下压 |
| 8. DISCHARGE_WASTE | 提示排放前段废粮 |
| 9. FORMAL_SAMPLING | 按粮食类型持续抽粮 |
| 10. CONVEY_1 | 启动输送机构 CH0、CH1 |
| 11. OPEN_BIN | 按浅层、中层、深层打开 CH2、CH3、CH4 |
| 12. CONVEY_DONE | 提示收粮，确认后关闭当前粮仓 |
| 13. NEXT_CHECK | 判断下一个深度、下一个点或任务结束 |
| 14. ALL_DONE_PROMPT | 提示所有采样完成 |
| 15. RETURN | 发布出发点作为返航目标，到达后结束任务 |

粮食类型对应的默认运行时间：

| 类型 | 抽粮或输送时间 |
|---|---:|
| 稻谷 | 120 秒 |
| 玉米 | 180 秒 |
| 大豆 | 90 秒 |

## 七、导航到达的判断方式

程序向以下话题发布目标：

```text
/move_base_simple/goal
```

然后等待以下任意一个信号：

```text
/waypoint_task_done = "arrive"
```

或者：

```text
/goal_controller/status
```

内容以 `ARRIVED` 开头。

当前主启动服务没有启动导航节点。运行假导航全流程测试时，可以发送假到达命令：

```bash
rostopic pub -1 /waypoint_task_done std_msgs/String "data: 'arrive'"
```

效果：

- 不让机器人实际导航。
- 通知 UI 已到达目标点。
- 让状态机继续执行上层机构动作。

返航阶段也需要再发送一次相同命令。

发送前可以检查是否存在导航控制器：

```bash
rostopic info /move_base_simple/goal
```

如果显示：

```text
Subscribers: None
```

说明当前发布目标不会驱动底盘自动移动。

## 九、底盘控制链路

主要文件：

```text
src/grain_sampling_workflow/rc_node.py
src/grain_sampling_workflow/rc_control.py
dipan/cmd_vel_to_motor.py
dipan/motor_driver.py
```

控制关系：

```text
遥控接收器
 → /dev/rc_receiver
 → rc_node.py
 → /cmd_vel
 → cmd_vel_to_motor.py
 → UDP 127.0.0.1:8765
 → motor_driver.py
 → PCA9685 CH10/CH9
```

差速计算：

```text
左轮 = 前后速度 - 转向速度
右轮 = 前后速度 + 转向速度
```

最终 PWM：

```text
PWM = 1500 + 速度 × 250 μs
```

如果超过 0.3 秒没有收到新指令，驱动程序会把两个通道恢复到 1500 μs 中位。

自动导航如果需要真正控制底盘，也必须最终向 `/cmd_vel` 发布速度。

## 十、UI 真实机构安全开关

当前 UI 默认不使能真实机构，避免误打开界面时机构动作。实机联调必须在启动 UI 前显式设置：

```bash
export GRAIN_SAMPLING_UI_ENABLE_MECHANISM=1
```

启用后，UI 创建调度器时会调用：

```python
orchestrator.enable_mechanism()
orchestrator.set_grain(grain_type)
```

未设置该变量时，状态会前进，但夹持、拧管、X2P、吸粮和输送服务不会被调用。实机运行时必须同时确认终端日志出现 `REAL MECHANISM MODE enabled`。

## 十一、深度逻辑不一致

当前每次下压距离：

```python
PRESS_STEP_CM = 20.0
```

但状态机把每次循环按一根 1 米管计算：

```text
循环 1 次 → 认为深度 1 米
循环 2 次 → 认为深度 2 米
```

因此，如果 UI 选择 2 米：

```text
代码实际执行：2 × 20 cm = 40 cm
状态机显示：2 m
```

除非机械结构能通过一次 20 cm 行程推进整根 1 米管，否则这里需要修改。

实机运行完整流程前，需要确认：

- 每根采样管的实际长度。
- X2P 单次应该运动多少厘米。
- 加管发生在上升之前还是之后。
- 深度应按累计电机行程还是管子数量计算。

## 十三、总结

当前项目已经具备以下完整软件骨架：

- systemd 开机服务。
- ROS 主节点和机构服务。
- 遥控器到底盘 PWM 输出。
- PCA9685 上层机构控制。
- X2P 伺服升降控制。
- UI 任务创建和流程提示。
- 采样状态机和 ROS 调用接口。
- 假导航到达测试方式。

但是，在真实全流程实机测试前必须优先处理：

1. 真实机构必须由 `GRAIN_SAMPLING_UI_ENABLE_MECHANISM=1` 显式启用。
2. 确认 20 cm X2P 行程与 1 m 深度之间的机械关系。
3. 接通并实现风机 CH7 的真实控制。
4. 如果需要自动行走，启动完整导航节点并保证其向 `/cmd_vel` 发布速度。

未设置真实机构环境变量时，UI 只执行模拟等待；即使已启用真实机构，完成深度标定前实际下管深度也可能与界面显示不一致。

## 十四、X2P 伺服升降手动微调程序

项目提供两个手动升降微调工具：

```text
scripts/move_lift.py           单次移动，通过 ROS 服务 /mechanism/move_lift 下发
scripts/manual_lift_adjust.py  交互式连续微调，直连串口，不依赖 ROS
```

两个工具都用于在调试、安装采样管或调整机构位置时，输入方向和距离，让 X2P 伺服升降机构相对当前位置移动。

`move_lift.py` 每次只下发一次动作，动作结束后程序立即退出，不会连续运行。

`manual_lift_adjust.py` 是交互式程序，反复输入“方向 + 距离”即可连续微调，适合上电后把不在物理最高点的机构一小段一小段挪回去。它不依赖 ROS，也不依赖 `/mechanism/move_lift` 服务，机构节点没起来也能用。详细说明见本节第 8 小节。

> 单独成册的完整使用文档：[grain_sampling_robot_software_share/docs/X2P手动调整初始位置使用说明.md](grain_sampling_robot_software_share/docs/X2P手动调整初始位置使用说明.md)，含命令表、参数表、真实输出示例与常见问题排查，可单独打印给现场操作人员。

### 1. move_lift.py 的控制原理

本节（第 1～7 小节）描述 `scripts/move_lift.py`；交互式手动调整程序见第 8 小节。

每次执行时，程序通过 ROS 调用：

```text
/mechanism/move_lift
```

底层读取当前编码器位置，并以当前位置为起点计算本次目标位置。因此该工具执行的是相对距离移动，不是移动到机械绝对坐标。

例如：

```text
当前位置 + 向上 2 cm → 从当前位置提升 2 cm
当前位置 + 向下 5 cm → 从当前位置下压 5 cm
```

该程序不会自动寻找机械零点，也不会判断机构目前位于总行程的哪个位置。

### 2. move_lift.py 使用前启动服务

在 3588 工控机上执行：

```bash

source /home/neardi/mechanism_ws/devel/setup.bash
sudo systemctl start grain-sampling
```

```bash

```

正常情况下应显示：

```text

```

### 3. move_lift.py 单次向上移动

从当前位置向上移动 2 cm：

```bash
python3 scripts/move_lift.py up 2
```

也支持中文方向参数：

```bash

```

### 4. move_lift.py 单次向下移动

从当前位置向下移动 2.5 cm：

```bash

```

也支持中文方向参数：

```bash

python3 scripts/move_lift.py 下压 2.5
```

### 5. move_lift.py 程序输出

执行前会显示即将运行的方向和距离，例如：

```text

```

执行完成后会显示 ROS 服务返回结果：

```text
执行结果：success=True，message=move_lift up 2.0cm ok: ...
```

如果显示 `success=False`，应停止继续操作并查看机构节点日志：

```bash
tail -f /tmp/grain_sampling_robot/mechanism_node.log
```

### 6. move_lift.py 单次距离安全限制

程序默认单次最多移动：

```text
20 cm
```

以下输入会被拒绝：

- 距离为 0。
- 距离为负数。
- 距离不是有效数字。
- 单次距离超过 20 cm。
- 方向不是 `up`、`down` 或支持的中文方向。

如果现场确实需要改变单次最大距离，可以使用环境变量。例如，把单次限制改为 10 cm：

```bash
MANUAL_LIFT_MAX_CM=10 python3 scripts/move_lift.py up 3
```

不建议为了长距离运动随意增大限制。更安全的做法是分多次小距离调整，并在每次动作后观察机构状态。

### 7. 手动调整安全要求

由于当前系统尚未实现机械原点回零和全行程软限位，手动调整时必须遵守以下要求：

1. 首次测试建议使用 `0.5～2 cm` 的小距离。
2. 执行前确认对应方向仍有足够机械行程。
3. 操作人员应留在急停按钮附近观察机构。
4. 不要在机构已经接近顶部或底部时继续向同一方向移动。
5. 出现异响、堵转、方向错误或位置误差时立即急停。
6. 不要把编码器当前计数误认为已经建立了机械零点。

紧急停止：

```bash
rosservice call /mechanism/emergency_stop
```

如果 ROS 服务无法响应，则停止整个项目服务：

```bash
sudo systemctl stop grain-sampling
```

### 8. 交互式手动调整程序（scripts/manual_lift_adjust.py）

#### 为什么需要这个程序

X2P 伺服没有断电保持的多圈绝对编码器：断电重新上电后编码器计数从零开始，驱动器并不知道升降机构此刻停在行程的哪个位置。

自动流程（`press`/`lift`、`sampling_press` 周期运动）执行的都是相对距离动作。如果上电时机构不在物理最高点，这些相对动作就会从错误的起点起算。手动调整程序的作用就是把这个不确定的起点人工挪回已知位置：操作员输入方向和距离，程序做一次编码器闭环的相对移动，反复执行直到机构回到物理最高点。

#### 8.1 与 move_lift.py 的区别

| 对比项 | `scripts/move_lift.py` | `scripts/manual_lift_adjust.py` |
|---|---|---|
| 依赖 | ROS + `/mechanism/move_lift` 服务 | 直连串口（Modbus RTU），不依赖 ROS |
| 交互方式 | 执行一次后退出 | 交互循环，可连续多次调整 |
| 机构节点 | 必须先启动 `grain-sampling` | 必须先停止 `grain-sampling`（串口独占） |
| 参考点 | 无 | 可用 `m` 记录最高点，配合 `--travel-mm` 做本次运行内的软限位 |

#### 8.2 使用前先释放串口

手动程序直接打开伺服串口，而机构节点 `mechanism_node` 启动时也会打开同一个串口。两者同时运行会互相打断 Modbus 帧，导致读位置或移动失败。所以手动调整前先停掉服务：

```bash
sudo systemctl stop grain-sampling
```

调整完成后重新启动：

```bash
sudo systemctl start grain-sampling
sleep 3
systemctl status grain-sampling --no-pager -l
```

#### 8.3 启动方式

在 3588 工控机上执行：

```bash
cd "/home/neardi/project/grain guard robot/grain-guard-robot/grain_sampling_robot_software_share"
export PYTHONPATH="$PWD/src${PYTHONPATH:+:$PYTHONPATH}"
python3 scripts/manual_lift_adjust.py
```

默认串口 `/dev/ttyS0`（板载 RS485），从站 2，转速 200 r/min，单次距离上限 20 cm。程序启动后先打印警告和当前编码器位置，然后进入提示符等待输入。

单次模式（执行一次后退出）：

```bash
python3 scripts/manual_lift_adjust.py up 0.5
python3 scripts/manual_lift_adjust.py down 1.2
```

只读位置（不移动机构）：

```bash
python3 scripts/manual_lift_adjust.py --status
```

#### 8.4 交互命令

| 输入 | 作用 |
|---|---|
| `up 0.5` | 从当前位置上升 0.5 cm |
| `down 1.2` | 从当前位置下降 1.2 cm |
| `up`（只给方向） | 程序追问本次距离后再执行 |
| `s` | 只读打印当前编码器位置，不移动 |
| `m` | 把当前位置记为“物理最高点”，仅本次运行有效 |
| `clear` | 清除上面记录的参考点 |
| `q` | 退出程序 |

方向别名：`up`、`上`、`上升`、`提升`、`forward`、`fwd`、`+`、`正向` 都表示上升；`down`、`下`、`下降`、`下压`、`reverse`、`rev`、`-`、`反向` 都表示下降。

每次移动前会打印目标方向、距离、驱动器方向、预计时长和停止容差；移动后打印实际编码器位移，位移明显偏小或方向相反时给出警告。

#### 8.5 只读确认驱动器状态

确认串口通了、驱动器没有报警时，可以直接读寄存器（同样建议先停服务）：

```bash
export PYTHONPATH="$PWD/src${PYTHONPATH:+:$PYTHONPATH}"
python3 -m x2p.cli --port /dev/ttyS0 status
python3 -m x2p.cli --port /dev/ttyS0 hybrid-status
```

`status` 输出里的 `servo_enabled` 就是 Un058，0 表示未使能。程序的停止基线用 Un058 + 实际转速判断，不使用固件自定义的 `status` 字段：本机固件在“未使能且静止”时上报 `status=3`，按 `status==1` 判断 OFF 会误报互锁并阻止所有移动。

#### 8.6 参数与环境变量

| 参数 | 说明 | 默认 |
|---|---|---|
| `--port` | 伺服串口（`X2P_PORT`） | `/dev/ttyS0` |
| `--slave` | Modbus 从站地址（`X2P_SLAVE`） | 2 |
| `--rpm` | 升降转速 r/min（`X2P_RPM`） | 200 |
| `--tolerance-mm` | 停止位置容差 mm | 2.0 |
| `--max-cm` | 单次移动上限 cm（`MANUAL_LIFT_MAX_CM`） | 20 |
| `--travel-mm` | 总行程 mm，配合交互命令 `m` 做本次运行内的软限位 | 0（不启用） |
| `--screw-lead-mm` | 丝杆导程 mm | 5.0 |
| `--forward-sign` | 升降方向翻转（`X2P_FORWARD_SIGN`） | 1 |
| `--status` | 只读打印编码器位置后退出 | 关闭 |

单次移动上限也可用环境变量临时修改：

```bash
MANUAL_LIFT_MAX_CM=10 python3 scripts/manual_lift_adjust.py up 3
```

#### 8.7 交互式手动调整的安全要求

除第 7 小节的通用要求外，还要注意：

1. 系统当前没有机械原点回零，也没有全行程软限位；`m` 记录的“最高点”和 `--travel-mm` 只在本次运行内有效，退出程序即失效。
2. 断电后编码器不保持计数，所以“最高点”不可能跨上电保存；每次上电后都需要重新判断机构位置。
3. 移动前先按 `s` 看当前位置，确认方向正确再加大距离；不确定时先用 0.5 cm 试方向。
4. 程序用 `Ctrl-C`（或 `SIGTERM`）退出时会尝试安全停机（写 0 转速并撤销软件使能）。
5. 调整结束后必须重新启动 `grain-sampling`，否则自动流程会因为机构节点没起来而全部失败。
