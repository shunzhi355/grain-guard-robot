# 机构动作串口接入（保留 PCA9685）

## 运行方式

2026-10-02 接入依据：[用户提供的单片机协议对话](https://chatgpt.com/s/cx_6abfa15183b48191876841cd0dd28cdd)的最终版本，以及本机 `D:\Project\下位机构\机构\MDK-ARM\MECHANISM_PROTOCOL.md`。采用“输粮两路联动、三仓单开”的新编号，不能混用对话前半部分旧的八设备编号。

生产入口 `grain_sampling_interhost.server` 默认启用。UI、正式采样流程和通过本机 Socket 操作的联调工具在触发机构动作时，会通过已有底盘串口发送对应命令，然后执行原 PCA9685 动作。PCA9685 驱动、脉宽、夹爪三线控制和原定时器均保留，X2P 升降仍走工控机原有 RS485 链路。

串口继续使用 `CHASSIS_SERIAL_PORT`，115200、8N1，无流控，只有一个串口句柄。机构和底盘帧共享 `ChassisSerial` 的非零发送方编号、递增序号及发送锁；接收不使用发送锁。编号用于帧识别，不需要与单片机握手建立会话。

## TX 发指令，RX 持续接收 CH8 状态

工控机和单片机按两个独立方向工作：

- 工控机 TX → 单片机 RX：发送底盘、夹爪、拧管、三仓和输粮动作。每条机构动作只发送一次，不等待 ACK、执行结果或完成回传，不因没有回传重发 START。
- 单片机 TX → 工控机 RX：单片机持续主动上报 CH8 自动／手动状态，工控机的 `chassis-rx` 线程持续读取。不发送状态查询，也不要求状态帧与某条指令的编号对应。

`chassis-rx` 每 10 ms 检查已缓冲数据，单次最多读取 4096 字节，串口 `timeout=0`；没有数据立即返回。底盘发送循环和机构发送均不调用串口读取，因此两个方向不会互相等待应答。多个发送者仍须共用发送锁，避免两条命令在 TX 上交错。系统写入保留 50 ms 超时，用于报告实际串口写故障。

接收沿用现有固件的 `STATUS (0x0A)` 帧及其 CH8 模式字段，无需更换线上的帧格式。固件已有的故障、急停和重启标志仍被动用于安全判断，不作为动作应答；不等待电机完成回传。超过 1 秒没有有效状态，界面模式为“未知”，撤销自动行驶并禁止新的自动机构动作；不会仅因没有状态帧反复关闭、重开串口。实际串口 I/O 错误才触发重连，重连不恢复旧动作。

急停复位在本机条件满足后发送停车及 `CLEAR_ESTOP`，写成功即解除本地锁定，不等待复位确认，也不恢复之前的任务。缓存的复位前急停状态不会再次锁定；新收到的急停状态仍会锁定。`execution_confirmed=false` 表示串口发送成功不等于单片机已执行。

直接实例化 `MechanismRuntime` 时，只有注入 `serial_command` 才会发机构串口命令；旧 ROS 包装和直接使用 `MechanismController` 的 PCA9685 工具保持原行为。部署时更新 `3588/src/` 并重启现有守护进程即可，无需更改 UI 或另开串口程序。

## 动作映射

以下命令、编号均为十六进制。PWM、占空比和运行时间不进入串口负载，由 MCU 本地参数决定。

| 上位机动作 | command / device | MCU 行为 |
| --- | --- | --- |
| `tighten` | `01 01` | 拧紧 |
| `convey` / `start_convey` | `01 02`，只发一帧 | 两路输粮同时启动 |
| `stop_convey` | `02 02` | 两路输粮同时停止 |
| `open_bin` / `hold_bin_open`，浅仓 | `01 03` | 开浅仓，同时关其他仓 |
| 同上，中仓 | `01 04` | 开中仓，同时关其他仓 |
| 同上，深仓 | `01 05` | 开深仓，同时关其他仓 |
| `open_bin_default` | `01 04` | 默认中仓 |
| `close_bin` | `02 03` / `02 04` / `02 05` | 对应仓执行关门动作 |
| `close_all_bins` | 依次 `02 03`、`02 04`、`02 05` | 三仓各自关门，不等待前一仓动作结束 |
| `clamp` | `01 06` | 夹紧 |
| `unclamp` | `01 07` | 松开 |
| `untighten` | `02 01` | 只停止 MCU 拧紧；反向拧松仍由原 PCA9685 执行 |
| 急停、退出、串口新建/重连 | `03 00` | 全部机构立即回安全停止态 |

`03 00` 不关仓，只让电调回 1500 μs、夹爪 nSLEEP 拉低；正常关仓必须用各仓的 `02`。启动/关仓在底盘未授权运动、串口在线、自动档且无底盘急停时放行。急停后的正常关仓也被禁止，因为关仓本身会驱动电机。

协议没有反向拧松、风机或升降设备编号；不会把这些动作误映射到其他电机。风机与 X2P 保留原路径。

## 帧与发送语义

固定 18 字节，多字节整数小端：

```text
A5 5A | 01 | 36 | 02 00 | sender:u32 | sequence:u32 | command:u8 | device:u8 | CRC16:u16
```

CRC-16/CCITT-FALSE：poly=0x1021、init=0xFFFF、不反射、xorout=0。覆盖偏移 2–15，CRC 本身也按小端发送。每个业务动作只发送一次，无握手、无机构 ACK、无自动 START 重发；串口写成功只代表已发送，不代表机构执行完成。

以 sender=`0x12345678` 为例：

```text
sequence=1，拧紧：
A5 5A 01 36 02 00 78 56 34 12 01 00 00 00 01 01 AA DB

sequence=4，全部停止：
A5 5A 01 36 02 00 78 56 34 12 04 00 00 00 03 00 E8 EE
```

分享对话中同一全部停止帧末尾写成 `EA 6B`，与定义的 CRC 算法不符；正确值为 `E8 EE`。实现复用既有底盘 CRC 编码器，测试同时使用固件文档的拧紧、输粮、开关仓、夹爪参考帧验证。

## 失败与退出

- 参数先校验，非法设备、命令、仓位不会发送启动帧。
- 串口离线/写失败不继续启动 PCA9685；若串口或 PCA9685 在动作中失败，尽力发送 `STOP_ALL`、停止本地机构并锁定后续动作，原异常返回给工作流。
- 机构启动与急停由同一机构锁排序，避免急停后补发旧启动命令。串口重连先发送底盘停车和机构全停，不缓存或重放动作。
- 正常退出先停止机构，再关闭共享串口。串口故障不会阻止 PCA9685 的本地停机。
- 链路物理断开时无法保证 `STOP_ALL` 到达。MCU 此版机构依靠本地动作时限回停，不能把底盘的 300 ms 运动断流保护当成机构看门狗。

## 时序边界与联调

这是动作通知接入，PCA9685 与 MCU 输出并行保留；两路信号不要并接到同一个电调信号脚。上位机原有流程等待和 PCA9685 定时保持原值，MCU 按自身固件运行，两者并不保证同时停止。

现有 MCU 文档默认：拧紧 3 秒、输粮 5 秒、开仓 5 秒后自动三仓全关（关仓 3 秒）、夹紧 2 秒、松开 5 秒。上位机输粮流程可能为 10/90/120 秒；`hold_bin_open` 的 PCA9685 行为是在开门动作后回中并保持仓位，而 MCU 到期会自动关仓。因此当前接入不能视为“已完全由 MCU 替代 PCA9685”；正式接管需另行对齐本地固件参数和仓门保持语义。本次未修改 MCU 源码/参数，也未用重复 START 延长动作。

软件回归不连接硬件。实机应在烧录上述最终协议固件后，通过已有 UI/联调工具依次检查：两路输粮只收到一条启动命令；三仓编号、单开和全关；夹紧/松开方向；急停全停；断串口后报错与重连不重放。单片机不回机构 ACK，最终 PWM、方向和动作完成需实测确认。
