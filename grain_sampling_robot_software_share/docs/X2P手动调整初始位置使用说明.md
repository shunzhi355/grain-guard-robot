# X2P 升降伺服手动调整初始位置程序使用说明

对应脚本：`scripts/manual_lift_adjust.py`
适用机型：临滴 NEARDI LPA3588（RK3588）工控机 + X2P 升降伺服
文档日期：2026-09-20

---

## 1. 这个程序解决什么问题

X2P 伺服**没有断电保持的多圈绝对编码器**。断电重新上电后，编码器计数从零开始，驱动器并不知道升降机构此刻停在行程的哪个位置。

而自动流程（`press` / `lift`、`sampling_press` 周期运动）执行的都是**相对距离动作**，全部从上电时刻的位置起算。如果上电时机构不在物理最高点，这些相对动作就会从错误的起点开始，导致下压深度、提升高度整体偏移。

本程序的作用就是把这个不确定的起点**人工挪回已知位置**：操作员输入方向和距离，程序执行一次带编码器反馈的相对移动，反复执行直到机构回到物理最高点。

### 1.1 适用与不适用

| | 说明 |
|---|---|
| 适用 | 上电后机构不在物理最高点；调试阶段需要手动挪动升降轴；自动流程起点明显偏移 |
| 适用 | 机构节点（`mechanism_node`）起不来、ROS 环境缺失时，仍要能动一下升降轴 |
| 不适用 | 需要系统自动找机械零点 —— 当前系统**没有**原点回零功能 |
| 不适用 | 长时间连续运动 —— 本程序是人工点动工具，不是自动流程替代品 |

## 2. 使用前提

1. 工控机已上电，X2P 伺服驱动器已上电，无报警。
2. 板载 RS485 设备 `/dev/ttyS0` 存在，当前用户在 `dialout` 组或等价权限。
3. 已安装 `pyserial`。
4. **手动程序运行时不能与机构节点同时占用串口**（见 2.1）。

检查串口是否存在、权限是否足够：

```bash
ls -l /dev/ttyS0
groups | tr ' ' '\n' | grep -E 'dialout|tty'
python3 -c "import serial; print('pyserial OK', serial.__version__)"
```

### 2.1 先释放串口（必须）

手动程序直接打开 `/dev/ttyS0`，而 `mechanism_node` 启动时也会打开同一串口，两边同时运行会互相打断 Modbus 帧，表现为读位置失败或移动异常。

调整前先停服务：

```bash
sudo systemctl stop grain-sampling
```

调整结束后再启动：

```bash
sudo systemctl start grain-sampling
sleep 3
systemctl status grain-sampling --no-pager -l
```

> 调整结束后**必须**把服务起回来，否则后续自动流程会因为机构节点没起来而全部失败。

---

## 3. 安全须知（请先读完再操作）

1. 系统当前**没有机械原点回零，也没有全行程软限位**。程序无法判断机构是否已经到顶或到底，越界保护依赖操作员。
2. 上电时机构可能停在任意位置，第一次移动**务必用 0.5～2 cm 的小距离**试探，不要一上来就给大距离。
3. 操作时人留在**硬件急停按钮**旁边。软件层面的停机（`Ctrl-C`、`q`）在串口异常时可能失效，急停才是最终手段。
4. 垂直轴断电可能因自重下滑；确认防坠装置或机械支撑有效后再操作。
5. 程序在 `Ctrl-C` / `SIGTERM` 时会**尽力**安全停机（写 0 转速、撤销软件使能），但这依赖串口仍然可用，不能当作安全功能。
6. 不确定方向是否正确时，先执行 0.5 cm，用移动后打印的“实际位移”判断，不要凭直觉加大距离。

## 4. 快速开始

```bash
# 1. 进入项目目录
cd "/home/neardi/project/grain guard robot/grain-guard-robot/grain_sampling_robot_software_share"
export PYTHONPATH="$PWD/src${PYTHONPATH:+:$PYTHONPATH}"

# 2. 停掉占用串口的服务
sudo systemctl stop grain-sampling

# 3. 先只读看当前位置，不移动机构
python3 scripts/manual_lift_adjust.py --status

# 4. 进入交互模式，反复输入方向和距离
python3 scripts/manual_lift_adjust.py

# 5. 调整完成后恢复服务
sudo systemctl start grain-sampling
```

不需要 `source /opt/ros/noetic/setup.bash` —— 本程序不依赖 ROS；工控机上也没有该文件。脚本自身会把 `src/` 加入 `sys.path`，上面第 2 行的 `PYTHONPATH` 只是显式兜底。

## 5. 交互模式详解

### 5.1 启动

```bash
python3 scripts/manual_lift_adjust.py
```

程序先打印一段横幅，包含当前关键参数和编码器位置，然后停在提示符等待输入：

```
========================================================================
X2P 升降伺服 —— 手动调整初始位置
========================================================================
警告：X2P 伺服没有断电保持的多圈编码器，上电后驱动器不知道机构停在行程的哪个位置。
警告：本程序只做相对移动，不会自动回机械零点；系统当前也没有全行程软限位。
本次运行：转速 200 r/min，单次距离上限 20 cm，位置容差 2 mm
行程软限位：未启用（可加 --travel-mm 指定总行程，再用 m 记录最高点）
当前编码器位置 1048576；尚未记录物理最高点（交互命令 m）
首次调试请用 0.5～2 cm 的小距离，并留在急停按钮旁边。
========================================================================
请输入命令（up/down + 距离cm；s 查看，m 记最高点，q 退出）>
```

### 5.2 命令表

| 输入 | 作用 |
|---|---|
| `up 0.5` | 从当前位置上升 0.5 cm |
| `down 1.2` | 从当前位置下降 1.2 cm |
| `up`（只给方向） | 程序追问距离后再执行 |
| `s` | 只读打印当前编码器位置，不移动 |
| `m` | 把当前位置记为“物理最高点”，仅本次运行有效 |
| `clear` | 清除上面记录的参考点 |
| `q` | 退出程序 |

`q` 的同义词：`quit`、`exit`、`退出`、`结束`。
`s` 的同义词：`status`、`状态`。
`m` 的同义词：`mark`、`原点`、`最高点`。
`clear` 的同义词：`清除`、`取消原点`。

### 5.3 方向别名

| 含义 | 可输入 |
|---|---|
| 上升 | `up`、`上`、`上升`、`提升`、`forward`、`fwd`、`+`、`正向`、`正转` |
| 下降 | `down`、`下`、`下降`、`下压`、`reverse`、`rev`、`-`、`反向`、`反转` |

方向映射与自动流程的 `grain_sampling_devices.x2p_lift._map_lift_direction` 一致：上升 = `forward`，下降 = `reverse`。

### 5.4 一次完整操作的样子

```
请输入命令（up/down + 距离cm；s 查看，m 记最高点，q 退出）> s
当前编码器位置 1048576；尚未记录物理最高点（交互命令 m）

请输入命令（up/down + 距离cm；s 查看，m 记最高点，q 退出）> m
已把当前编码器位置 1048576 记为物理最高点（只在本次运行内有效）。
提示：未指定 --travel-mm，因此不会做行程软限位。

请输入命令（up/down + 距离cm；s 查看，m 记最高点，q 退出）> down 1.2
准备执行：下降 1.2 cm（驱动器方向 reverse，时长 0.86 s，容差 2 mm）；本程序不会自动寻找机械零点。
[伺服] MOVE_BEGIN start=1048576 target=734003 distance_mm=12.0 tolerance_mm=2.0 cruise_rpm=167 approach_rpm=12 approach_window_mm=12.000
[伺服] 位置: 1048576 pulse, 剩余: 314573 pulse, 速度: -12 r/min
[伺服] 位置: 917504 pulse, 剩余: 183501 pulse, 速度: -12 r/min
[伺服] MOVE_STOP start=1048576 target=734003 final=786432 error_mm=-2.0000 tolerance_mm=2.0
实际位移 -10.000 mm（目标 12 mm；编码器 1048576 → 786432）
距记录的最高点 10.000 mm
执行完成。

请输入命令（up/down + 距离cm；s 查看，m 记最高点，q 退出）> s
当前编码器位置 786432；距记录的最高点 10.000 mm

请输入命令（up/down + 距离cm；s 查看，m 记最高点，q 退出）> q
退出手动调整程序。
```

上面这段是程序在本机编码器闭环路径下的**真实输出格式**（`[伺服]` 前缀来自驱动器控制器层）。注意 `目标 12 mm`、`实际 -10.000 mm` 之间差了 2 mm，正好等于本次的停止容差，属于正常到位；容差内的小偏差是允许的。

### 5.5 输出怎么读

| 输出 | 含义 |
|---|---|
| `驱动器方向 forward/reverse` | 实际下发给驱动器的方向名，用于核对接线方向 |
| `时长 X s` | 按转速和丝杆导程算出的**标称巡航时长**（见 5.6），不是真实总耗时 |
| `容差 X mm` | 停止位置容差；距离过小时程序会自动收紧并提示 |
| `实际位移 +X mm` | 用编码器前后差值算出的真实位移，正值=上升 |
| `距记录的最高点 X mm` | 正值=还在最高点下方，负值=已越过记录点 |
| `[伺服] MOVE_BEGIN …` | 运动开始：起点、目标计数、距离、容差、巡航/接近转速 |
| `[伺服] 位置: … pulse, 剩余: … pulse, 速度: … r/min` | 运动过程中的周期遥测（约每 0.25 s 一行） |
| `[伺服] MOVE_STOP … error_mm=…` | 运动结束：终点计数与相对目标的误差 |
| `警告：实际位移明显小于目标…` | 可能卡阻、限位或方向设置有问题，请停机检查 |
| `警告：编码器位移方向与指令相反…` | `forward_sign` 或接线方向需要确认 |

### 5.6 两个容易误判的真实行为

**第一：小距离移动会明显比打印的“时长”慢。**

程序打印的“时长”是按转速和丝杆导程算出的**标称巡航时长**。控制器为了不冲过目标，在接近目标时会切到**低速接近段**；距离越短，低速段占的比例越大，小距离甚至会全程低速，于是真实耗时远长于标称值。

以本机默认参数（导程 5 mm、转速 200 r/min、容差 2 mm）为例，下表的“预计真实耗时”是用控制器源码里的接近段算法（`_approach_profile`）逐项算出来的，不是估摸值：

| 移动距离 | 打印的标称时长 | 预计真实耗时 | 状态 |
|---|---|---|---|
| 0.5 cm | 0.36 s | 5.0 s | 全程低速（12 r/min） |
| 1.0 cm | 0.72 s | 10.0 s | 全程低速 |
| 1.2 cm | 0.86 s | 12.0 s | 全程低速 |
| 2.0 cm | 1.44 s | 20.0 s | 全程低速 |
| 3.0 cm | 2.16 s | 28.0 s | 先巡航，末段低速接近 |
| 5.0 cm | 3.60 s | 29.4 s | 先巡航，末段低速接近 |
| 10 cm | 7.20 s | 33.0 s | 先巡航，末段低速接近 |
| 20 cm | 14.4 s | 40.2 s | 先巡航，末段低速接近 |

（程序内部还会按“预计时长 + 25% 余量”作为超时上限，所以实际等待时间略长于表中数值是正常的。）

所以看到程序“半天没动完”是正常现象，**不要因为等不及就按 `Ctrl-C` 或断电**。低速接近正是机构能准确停位的原因。

**第二：实际位移可能比要求的距离短最多一个容差。**

控制器判断“到位”的条件是**剩余距离进入容差**，因此它会在距目标 `容差` 以内就停下来，不会硬凑到精确值。默认容差 2 mm 时，你输入下降 1.2 cm，实际可能只下降 1.0 cm 左右。这在“往最高点回”的场景是偏保守的（宁可少走，不会冲过头），但如果需要精确对位，应当：

- 先用小距离靠近，再用更小的容差补一次，例如 `--tolerance-mm 0.5`；
- 或者接受容差内的偏差，靠 `s` 反复确认“距记录的最高点”读数。

容差也不能随意缩到极小：容差越小，低速接近段的速度越低，移动会越慢（接近速度与容差成正比）。

## 6. 单次模式与只读模式

不需要连续调整时，可以直接给一条命令，执行完即退出。

```bash
# 上升 0.5 cm 后退出
python3 scripts/manual_lift_adjust.py up 0.5

# 下降 1.2 cm 后退出
python3 scripts/manual_lift_adjust.py down 1.2

# 只读打印当前编码器位置，不移动机构
python3 scripts/manual_lift_adjust.py --status

# 指定其它串口 / 从站 / 转速
python3 scripts/manual_lift_adjust.py --port /dev/ttyS0 --slave 2 --rpm 60 up 0.5
```

`--status` 是**唯一完全不发运动指令**的模式，适合在动手之前先确认串口通了、编码器能读数。

## 7. 参数与环境变量

### 7.1 命令行参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--port` | 伺服串口（环境变量 `X2P_PORT`） | `/dev/ttyS0` |
| `--slave` | Modbus 从站地址（`X2P_SLAVE`） | `2` |
| `--rpm` | 升降转速 r/min（`X2P_RPM`） | `200` |
| `--tolerance-mm` | 停止位置容差 mm | `2.0` |
| `--max-cm` | 单次移动上限 cm（`MANUAL_LIFT_MAX_CM`） | `20` |
| `--travel-mm` | 总行程 mm，配合交互命令 `m` 做本次运行内的软限位 | `0`（不启用） |
| `--screw-lead-mm` | 丝杆导程 mm | `5.0` |
| `--motor-revs-per-screw-rev` | 电机转数 / 丝杆转数 | `1.0` |
| `--forward-sign` | 升降方向翻转，只接受 `1` 或 `-1`（`X2P_FORWARD_SIGN`） | `1` |
| `--status` | 只读打印编码器位置后退出 | 关闭 |

默认值优先从 `sampling_params.py` 读取（`X2P_PORT`、`X2P_SLAVE`、`X2P_RPM`、`X2P_FORWARD_SIGN`、`X2P_POSITION_TOLERANCE_MM`），读不到才用内置兜底值。优先级：**命令行 > 环境变量 > `sampling_params.py` > 内置兜底**。

### 7.2 环境变量示例

```bash
# 临时把单次移动上限收紧到 10 cm
MANUAL_LIFT_MAX_CM=10 python3 scripts/manual_lift_adjust.py up 3

# 换串口
X2P_PORT=/dev/ttyUSB0 python3 scripts/manual_lift_adjust.py --status

# 降低转速慢慢试方向
X2P_RPM=60 python3 scripts/manual_lift_adjust.py up 0.5
```

程序启动时会校验参数：`--rpm`、`--max-cm`、`--tolerance-mm` 必须大于 0，`--travel-mm` 不能为负，`--forward-sign` 只能是 `1` 或 `-1`。参数不合法时以退出码 `2` 结束并打印原因。

## 8. 建立“最高点”参考与行程软限位

程序本身不存储原点，但可以在**一次运行内**记住一个参考点，用来提示还有多远、并拒绝越界移动。

```bash
python3 scripts/manual_lift_adjust.py --travel-mm 300
```

启动后：

1. 先把机构挪到物理最高点（人工判断，或用已知的机械基准）。
2. 输入 `m`，程序把这时的编码器计数记为“最高点”。
3. 之后每次移动前后都会打印“距记录的最高点 X mm”。
4. 如果某次移动会越过这个点，或超过 `--travel-mm`，程序会**拒绝执行**并提示。

```
请输入命令（up/down + 距离cm；s 查看，m 记最高点，q 退出）> up 5
拒绝执行：本次移动会越过记录的最高点（超出 12.400 mm）；请先用 m 重新记录最高点
```

**这个参考点只在本次运行内有效**：`clear` 可以手动清除，退出程序后失效，断电重启更不可能保留（编码器本身就不保持）。每次上电都要重新判断机构位置。

## 9. 工作原理

程序不依赖 ROS，直接经 RS485 用 Modbus RTU 操作驱动器，核心是**转速控制 + 编码器反馈**的相对移动：

1. 读当前编码器计数作为起点。
2. 按 `距离 = 丝杆导程 × 电机转数 / 传动比` 反算需要的电机转数，再按转速换算时长：

   ```
   时长 = (距离mm / 丝杆导程mm × 传动比) × 60 / 转速rpm × 1.2
   ```

   其中 `×1.2` 留 20% 余量，与自动流程 `mechanism_node._handle_move_lift` 的算法一致，保证手动与自动的速度、接近段行为相同。
3. 下发转速指令，运动过程中监控编码器，进入接近窗口后降速，靠容差判断到位后停机。
4. 读结束编码器计数，算出实际位移并打印。

当前默认参数下（导程 5 mm、转速 200 r/min），移动 1 cm 对应约 0.72 s 的运动时长。

### 9.1 停机判据为什么用 Un058

程序的“已停机/未使能”判据读的是 **Un058（伺服使能监视，0=未使能）** 加实际转速，**不使用**固件的 `status` 字段。

原因：本机固件在“未使能且静止”时上报 `status=3`，早期代码按 `status==1` 判断 OFF，会误判为“外部 S-ON 仍然有效”并阻止所有移动（现象是报错 `取消软件使能后仍未进入OFF`）。改用 `Un058` + 实际转速后，判据与真实状态一致。

驱动器真报警（`status=4`）时，程序会直接读 `Un100` 故障码并抛出 `E码`，而不是空等超时。

只读核对驱动器状态：

```bash
export PYTHONPATH="$PWD/src${PYTHONPATH:+:$PYTHONPATH}"
python3 -m x2p.cli --port /dev/ttyS0 status
python3 -m x2p.cli --port /dev/ttyS0 hybrid-status
```

`status` 输出里的 `servo_enabled` 就是 Un058。

> 上述两个只读命令同样会打开串口，因此也要先停服务。

## 10. 常见问题与排查

### 10.1 `打开或初始化 X2P 失败`

- 确认服务已停：`sudo systemctl stop grain-sampling`
- 确认串口存在：`ls -l /dev/ttyS0`
- 确认权限：`groups` 里有 `dialout`，否则用 `sudo` 或联系管理员加组
- 确认 `pyserial` 已装：`python3 -c "import serial"`

### 10.2 `无法导入 x2p 包`

脚本会把项目 `src/` 自动加入 `sys.path`，若仍报错，手动设置后重试：

```bash
export PYTHONPATH="$PWD/src${PYTHONPATH:+:$PYTHONPATH}"
```

### 10.3 驱动不动，但程序不报错

1. 读一下状态确认使能情况：`python3 scripts/manual_lift_adjust.py --status`
2. 若提示伺服使能超时，检查 DI1 / SRV-ON 接线、外部急停和驱动器报警。
3. 若驱动器显示报警，用 `python3 -m x2p.cli --port /dev/ttyS0 status` 看 `status`，报警时程序会给出 `E码`。

### 10.4 `取消软件使能后仍未停机：Un058=…，实际转速=… r/min`

这是**真实**的未停机：软件已撤销使能，但 `Un058` 仍非 0 或电机仍在转。可能原因：

- 外部 S-ON 端子仍然有效（硬件强制使能），需要查接线。
- 有外力拖动机构。
- 驱动器报警或处于保护状态。

停在原地排查，不要反复重试。

### 10.5 方向反了

两种处理方式，任选其一（不要同时改）：

```bash
# 方式一：只影响本次手动程序
python3 scripts/manual_lift_adjust.py --forward-sign -1 up 0.5

# 方式二：改现场配置，手动与自动一起生效
# 编辑 sampling_params.py 的 X2P_FORWARD_SIGN = -1（或设置同名环境变量）
```

改完先用 0.5 cm 验证，再恢复正常使用的距离。

### 10.6 `实际位移明显小于目标`

通常意味着卡阻、撞到机械限位或负载过大。立即停止，检查机构后再说。不要靠加大距离“冲过去”。

### 10.7 `拒绝执行：单次距离 … 超过安全上限`

默认单次上限 20 cm。需要更长距离时**分多次移动**，或显式提高上限：

```bash
MANUAL_LIFT_MAX_CM=40 python3 scripts/manual_lift_adjust.py down 30
```

提高上限前先确认行程余量。

### 10.8 调整后自动流程仍偏移

手动调整只能把机构挪回最高点，不改变自动流程的相对距离设定。若回到最高点后自动流程仍有固定偏差，应检查 `sampling_params.py` 里的下压/提升距离参数，而不是继续手动挪。

## 11. 与其它工具的关系

| 工具 | 依赖 | 用途 |
|---|---|---|
| `scripts/manual_lift_adjust.py` | 直连串口，不依赖 ROS | 上电后人工把机构挪回最高点，可连续微调 |
| `scripts/move_lift.py` | ROS + `/mechanism/move_lift` 服务 | 服务层单次移动，用于联调验证 ROS 通路 |
| `python3 -m x2p.cli status` | 直连串口 | 只读核对驱动器状态寄存器 |
| 自动流程 `press` / `lift` | ROS + 机构节点 | 正常作业，必须建立在正确起点上 |

`scripts/move_lift.py` 需要机构节点已经运行，本程序则要求机构节点**不要**运行，两者使用场景互斥。
