# 上层机构复测与日志

先同步本次修改到工控机。日志默认保存到项目 `log/hardware/启动时间-随机后缀/`，
`log/hardware/latest` 指向最近一次服务启动（包括失败启动）；UI 每次运行保存到
`log/ui/时间-PID.log`。旧日志不覆盖、不自动清理，定期归档并检查磁盘空间。
可用 `GRAIN_ROBOT_LOG_DIR`（硬件配置文件或服务环境）和 `GRAIN_UI_LOG_DIR` 修改目录。
若复用已经运行的节点，其输出仍在原日志中；完整复测应先停止旧 UI 和服务。

重启不是机械回零，也不会清除 UI 的未完成任务。上次发生超程后，先确认急停、
限位、防坠和实际安全起始位置；不要把重启当作恢复原点。不得无人值守连续复测。

## 终端一：重新启动服务

先在 UI 停止任务，安全停止机构后关闭旧 UI。必要时使用物理急停。

```bash
cd "/home/neardi/project/grain guard robot/grain-guard-robot/grain_sampling_robot_software_share"
source /home/neardi/mechanism_ws/devel/setup.bash
sudo systemctl stop grain-sampling
# 保留旧版本 /tmp 日志，执行一次即可；源不存在时跳过
if [ -d /tmp/grain_sampling_robot ]; then
  mkdir -p log
  cp -a /tmp/grain_sampling_robot "log/legacy-$(date +%Y%m%d-%H%M%S)"
fi
sudo systemctl reset-failed grain-sampling
sudo systemctl start grain-sampling
systemctl status grain-sampling --no-pager -l
rosservice list | grep /mechanism/
tail -F log/hardware/latest/mechanism_node.log
```

启动失败不要继续 UI 操作，查看 `startup.log` 和
`journalctl -u grain-sampling -n 100 --no-pager`。

## 出现异常时

立即停止任务；有碰撞/坠落风险时使用物理急停。记录第几次夹管、下压还是回升、
实际起点与终点、现场时间。不要连续点重试或恢复任务。

日志中的 `MOVE_REQUEST` 包含请求编号、方向、距离；`MOVE_BEGIN`/`MOVE_STOP`
包含编码器起点、目标、终点和误差；`MOVE_FAILED` 保存异常堆栈。
USB 中断时可能无法取得终点，不会伪造最终位置。
如果现场配置了外部 X2P 包，日志会标明加载路径；需同步修改该包或使用项目内版本，
否则可能没有新增的编码器起终点日志。

本次已禁止工作流 press/lift 和 move_lift 服务在失败后自动重发完整相对行程。
尚未改为绝对原点回程，因此仍需实测排查累计误差；默认机构调用容差仍为 15mm。

安全停止后打包日志（包括服务日志）：

```bash
journalctl -u grain-sampling --since today --no-pager > log/service-journal.txt
tar -czf "grain-test-$(date +%Y%m%d-%H%M%S).tar.gz" log
```

UI 日志记录 Python 输出和异常及 faulthandler 堆栈；底层库直接写入系统 stderr 的
部分提示可能仅出现在终端。硬件子进程 stdout/stderr 均完整重定向保存。
