# 联想单机迁移：代码与模拟验证

## 本轮边界

根据现场确认，本轮只修改代码并运行内存模拟；不连接联想 `192.168.1.200`，不打开真实串口，不发机构、伺服或底盘实机指令，不修改或烧录 STM32 固件。现有 3588 启动脚本、配置与生产部署保持不变。物理 PCA9685 已移除，新增机构路径不依赖它。

本轮不是全套 UI/导航迁移完成。`BenchSession` 是可复用的本机硬件验证集成层，不是 GRICP 服务端的直接替换；导航进程接入、UI 接入、真实端口身份检查、系统服务与现场验收仍需后续完成。新增 CLI 故意没有 `--execute`、`--port`、SSH 或自动部署选项，不能用模拟参数误启动设备。

## 实现范围

| 文件 | 作用 |
| --- | --- |
| `scripts/bench_hardware.py` | 默认且仅支持模拟；输出 JSON 报告、X2P 运动日志；失败退出码非零 |
| `src/grain_sampling_bench/mechanisms.py` | 纯 STM32 机构命令适配；无 I2C、PCA9685；定时输粮为可取消的阻塞动作 |
| `src/grain_sampling_bench/session.py` | 单一底盘串口所有者、动作授权、故障锁存、停止结果记录、X2P 动作取消 |
| `src/grain_sampling_bench/simulators.py` | STM32 字节帧/状态/ACK 模型及 X2P Modbus 寄存器模型 |
| `src/grain_sampling_bench/runner.py` | 18 个集成场景、连续绝对目标往复、并行负载和故障注入 |
| `test/test_hardware_bench.py` | 与原 3588 串口动作逐项对照、并发取消、禁止实串口及报告真实性测试 |

原驱动仅增加两个可选接口，默认行为不变：

- `ChassisSerial.mechanism_command(..., write_guard=None)`：只在串口写入期间持有检查/互斥，不占用 ACK 等待时间，防止待发送动作越过急停。
- `MotionController(..., cancel_check=None)`：在使能前、触发前、触发读回复核及运动监控中检查取消；停止路径不受取消检查阻挡。

验证层机构 ACK 超时/拒绝后立即锁存，不采用原生产控制器的跨重连重试策略。它发送同样的动作命令，但不会为了继续测试重放一个结果不确定的动作。此差异是验证层的保守故障处理，不修改 3588 生产调用默认行为。

## 机构串口行为：按现有 3588 顺序

使用已有 `A5 5A` 帧、CRC、会话/序号及共享 UART；有确认的动作使用 `0x38`，接受回传使用 `0x37`。紧急停止和无需确认的停止使用 `0x36`。命令接受 ACK **不是动作到位反馈**。

| 动作 | 串口负载 `(command, device)` |
| --- | --- |
| 拧紧 / 拧松 | `(1,1)` / `(2,1)` |
| 夹紧 / 松夹 | `(1,6)` / `(1,7)` |
| 输粮开始 / 停止 | `(1,2)` / `(2,2)` |
| 定时输粮 | 开始，等待配置时长或取消，再停止；模拟可显式缩短等待 |
| 浅 / 中 / 深仓开启 | 对设备 `3 / 4 / 5` 连发两次 `(1,device)`，序号不同 |
| 指定仓保持开启 | 目标仓两次开启，再依次对其他仓发送 `(2,device)` |
| 指定仓关闭 | `(2,device)`；注意它是会运动的关仓动作，不是安全静止命令 |
| 默认开仓 | 中仓两次开启 |
| 关闭全部仓 | `(2,3)`、`(2,4)`、`(2,5)` |
| 所有机构停止 | `(3,0)`，不是依次关闭三个仓 |

“拧松”严格沿用原串口流程的 `STOP TIGHTEN`，本轮不新增指令，也不修改固件。是否真的完成反向拧松仍属于实机验收，报告不把这一项的帧一致性标为机械通过。

原流程的 `start_suction/stop_suction` 没有 STM32 串口帧，验证入口明确报“不支持该串口动作”，不凭空增加设备号。X2P 升降使用已有 Modbus 运动驱动；完整取样工作流、松夹后回升等工艺层联锁不是本轮模拟全部覆盖的对象，后续接入 UI 时必须继续保留原工艺流程。

## 安全与故障行为

1. 本地导航速度仍须先 `arm(goal_id)`，使用返回的 epoch 调用 `command(epoch, vx_mm_s, wz_mrad_s)`；底盘仍走原 `ChassisController`，没有新增绕过接口。
2. 速度更新超时沿用 200 ms 配置。实际发现和发出停车还受 50 ms 底盘循环、调度和串口延迟影响；软件测试不是硬实时停止证明。
3. 新机构动作只能在底盘未授权移动时开始。并行测试先启动输粮，再授权底盘，然后运行 X2P 往复；不取消原有“移动中禁止新机构动作”的约束。
4. 手动档、遥控状态过期、STM32 重启/故障、急停、障碍、底盘授权丢失、串口句柄变化均会撤销本轮任务，提交底盘停止、STM32 `STOP_ALL` 和 X2P 停止。恢复通信不会恢复任务。
5. X2P 位置判断读实际编码器，不以命令位置冒充到位；每次回程使用记忆的绝对起点。位置触发 `Pn701=1` 不因丢 ACK 自动重发；异常后不自动回零。
6. 活跃 X2P 动作在同一所有者线程观察取消并执行停止，避免另一线程停车与新触发交错；USB/Modbus 调用可能阻塞到超时，因此取消不是硬件急停替代品。
7. USB 已断开时只能记录“停止未确认”。STM32 `STOP_ALL` 没有机械完成确认，成功写出也只记 `submitted`；X2P 只有读回 OFF/零速完成才记 `verified_off`。模拟器中的确认仍不等于实机确认。
8. STM32 重新枚举后，已锁存会话只补发停止，不重发动作。X2P 不自动重新打开或继续下一段运动；需人工检查后创建新会话。

本轮没有证明 STM32 连续输粮在主机断电/串口拔除后能独立停机，也没有证明 X2P 断链后能独立停机。现场必须用可用的硬件急停/驱动器失联保护验证，不能依赖已断开的串口发停止。

## 运行方法

需要 Python 3.10 或以上。完整保留仓库中的 `3588/` 与 `LENOVO/` 两目录，验证入口通过明确的导入顺序复用前者驱动，避免误导入联想目录里的旧协议包。

在仓库根目录运行，推荐使用单独虚拟环境：

```bash
python -m pip install -r LENOVO/requirements-bench.txt
python LENOVO/scripts/bench_hardware.py --simulate --cycles 100 --report .codex-tmp/lenovo-sim-100cycles.json
python -m pytest -o addopts= -q LENOVO/test/test_hardware_bench.py
```

`--cycles 100` 分别在独立往复、底盘+输粮+伺服并行场景执行 100 个往返；模拟位移为 5 mm，时间加速，不代表实机长稳测试时长。真实驱动的 Modbus 事务间隔在模拟注入中设为零以加速，生产默认 50 ms 没有改动。

报告不能覆盖已有同名文件，请每次换新名字。可用 `--scenario combined` 单独运行并行场景，也支持下列场景名称：

```text
stm32_actions           x2p_reciprocation     combined
navigation_timeout      stm32_manual          stm32_stale
stm32_rc_stale          stm32_estop           stm32_fault
stm32_obstacle          stm32_reboot          stm32_disconnect
stm32_lost_ack          stm32_corrupt_ack     stm32_rejected
x2p_drop_ack            x2p_disconnect        x2p_frozen_encoder
```

JSON 包含每场景断言结果、串口帧十六进制、序号、故障/恢复事件、停止尝试结果、位置序列、运行平台与源码 SHA-256。`passed=true` 仅表示选择的模拟场景断言通过；始终包含：

```json
{
  "mode": "simulation",
  "physical_hardware_verified": false,
  "decision": "PENDING_HARDWARE_VALIDATION"
}
```

## 后续现场验收与架构决策

目前只知道联想 IP，不知道其系统、登录方式、真实串口身份和现场安全状态；本轮不据此执行远程操作。进入实机阶段前需确认这些信息并单独授权动作测试。

| 门槛 | 必须实际验证 | 结果用途 |
| --- | --- | --- |
| STM32 迁移 | 联想上按稳定 USB 身份定位端口；拧紧/拧松、夹紧/松夹、三仓全部开闭、输粮开始/停止/定时；现场其他机构；档位回传、手自动切换、急停及恢复后不自启 | 全部动作由现场确认，不能用 ACK 替代 |
| X2P 迁移 | USB-RS485 往复与并行负载；实际编码器读回、限位/行程、USB 掉线/重枚举计数、超时/CRC 错误、断链停止和重新接入不自启 | 比较与原 3588 稳定连接的表现 |
| 完整本地集成 | UI 与雷达/导航共同负载下的速度授权、更新超时停车、进程退出/重启、硬件急停以及原取样工艺联锁 | 满足交付任务后再切生产 |

建议现场往复先做低速、短行程、少循环确认方向和急停，再按项目约定的交付时长进行长稳及故障注入；不要直接将模拟的 100 次参数用于未确认行程的实机。记录系统 USB 事件及串口稳定路径，模拟的 `simulated_reenumeration` 不是系统驱动重枚举测试。

前两项全部通过且完整集成验收通过，选择全迁联想；X2P 仍掉线且无可用稳定接口，则保留 3588 硬件守护进程。不能用本轮模拟结果替代这个选择门槛。
